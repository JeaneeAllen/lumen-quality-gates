Lumen Quality Gates: rollback demonstration (Stage 7)
====================================================

Goal: ship a release that passes every quality gate but publishes the wrong business data,
roll it back with git revert through a pull request, and verify that the deployed report
returns to its prior content and business metrics.

Timeline (UTC, 2026-10-12)
  Known good  532368b  merge PR #2                 run 38190752145  deployment 7004362562  01:09
  Bad release e38c3a9  merge PR #3 (staging-v2)    run 38191179042  deployment 7004427810  01:15
              746938c  release_label staging-v1 -> staging-v2; CI data seed 42 -> 7
  Rollback    3f94a2f  merge PR #4                 run 38191329330  deployment 7004451691  01:18
              2088c3c  git revert -m 1 e38c3a9; file tree identical to 532368b (git diff: none)

Why staging-v2 was "bad": the seed-7 batch is valid data (tests, contract, gate, and report all
passed), but it is not the intended batch, so every business metric changed. Quality gates prove
data is valid; they do not prove a release is the intended one. Rollback is the recovery.
